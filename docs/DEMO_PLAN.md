# LOOKFIT 시연 계획서

작성 2026-09-28. 기능을 넓게 늘리지 않고, 시연에서 확실하게 보여줄 4가지를 깊게 만든다.

## 1. 현재 부족한 점 (시연 관점)

| 구분 | 현재 상태 | 시연에서 드러나는 문제 |
| --- | --- | --- |
| 측정 → 사이즈 | 추천 사이즈를 가슴·허리 구간 하나로만 정함. 상품마다 사이즈표가 거의 같음 | "측정했더니 뭐가 좋아졌나"를 설명할 수 없음. 오버핏·슬림핏 상품도 같은 사이즈 추천 |
| AR 사이즈 | S~XL을 바꾸면 모든 옷이 똑같이 ±7% 커짐 | 내 몸과 상품 치수의 관계가 보이지 않음. 사이즈 버튼이 장식처럼 보임 |
| 실사 옷 AR | 상품 사진(p01–p09) 소매가 몸판과 한 장이라 팔을 들어도 소매가 따라오지 않음 | 팔을 움직이는 순간 "스티커"처럼 보임. 대표 상품일수록 티가 남 |
| 착용샷 | 저장하면 PNG 다운로드만 됨 | 여러 벌 입어보고 비교·결정하는 흐름이 없음. 시연 중 다운로드 창이 쌓임 |
| 시연 안정성 | 첫 실행 때 모델 다운로드(포즈 약 3초, 의류 분할 약 8초) | 시연 도중 대기 시간이 생기고, 카메라 권한 문제를 현장에서 발견하게 됨 |

## 2. 시연 핵심 기능 4가지

### ① 핏 엔진: 내 치수 × 상품 실측 → 상품별 사이즈와 부위별 핏

- 상품마다 핏 스타일(슬림 · 레귤러 · 오버 · 크롭 · 구조 · 롱)과 성별에 맞는 사이즈별 실측표를 만든다.
- 측정 치수와 비교해 부위별 여유를 cm로 계산한다: 어깨 · 가슴 · 총장 · 소매 / 허리 · 엉덩이 · 기장.
- 추천 사이즈는 "디자이너가 의도한 여유"에 가장 가까운 사이즈로 정한다. 그래서 오버핏 재킷은 오버핏답게 입히는 사이즈를 추천한다.
- 상세 페이지에 "내 몸 기준 핏" 카드를 둔다. 사이즈를 바꾸면 부위별 여유와 상태(끼임 · 딱 맞음 · 여유 · 큼)가 바로 바뀐다.
- 완료 기준: 같은 사람이라도 슬림핏과 오버핏 상품의 추천 사이즈가 다르다. 사이즈를 바꾸면 cm 수치가 바뀐다. 측정 전에는 키·몸무게 추정값으로 보여주고 "추정"이라고 표시한다.

### ② AR 핏 맵: 입은 채로 사이즈를 바꾸면 실제 치수만큼 옷이 변한다

- AR에서 사이즈를 바꾸면 "상품 실측 ÷ 내 치수" 비율로 옷 폭이 변한다. 추천 사이즈가 기준 폭이다.
- 몸 위에 부위별 핏 라벨(어깨 · 가슴/허리 · 기장)을 색으로 표시한다. 초록은 딱 맞음, 주황은 여유 또는 타이트, 빨강은 끼임이다.
- 완료 기준: 작은 사이즈를 고르면 옷이 좁아지고 라벨이 "끼임"으로 바뀐다. 키보드 ↑↓와 사이즈 버튼 모두 동작한다. 라벨은 끌 수 있다.

### ③ 실사 옷이 팔을 따라 움직인다 (소매 리깅)

- 상품 사진에서 팔꿈치·손목 위치를 찾아 앵커에 추가하고, 소매 부분을 몸판에서 분리한다.
- 소매는 사용자의 어깨 → 팔꿈치 → 손목을 따라 휘어서 그리고, 소매를 떼어 낸 옆구리는 바로 안쪽 몸판 원단을 밀어 채운다.
- 룩키에게 입힐 때도 소매가 A자 팔을 따라간다.
- 완료 기준: 실사 상의·전신(p01 · p03 · p04 · p06 · p08)과 사진으로 등록한 옷 모두, 팔을 들면 소매가 팔 위에 그려진다(자동 테스트로 픽셀 확인).

### ④ 룩 앨범과 비교: 여러 벌 입어보고 고른다

- 착용샷(버튼 · T 키 · 양손 제스처)을 앱 안 룩 앨범에 저장한다(최대 8장, 이 기기에만 저장).
- 두 룩을 나란히 비교하고, 각 룩의 상품 · 사이즈 · 합계 가격 · 핏 요약을 보여준다.
- 이 룩 다시 입기, 룩 통째로 장바구니, 이미지 다운로드, 삭제를 지원한다.
- 완료 기준: 타이머 촬영 3번 → 앨범 3장 → 2장 선택 비교 → 한 룩 담기가 끊김 없이 된다.

### 보조: 시연 준비 버튼

- MY 화면의 "시연 준비"를 누르면 포즈 모델과 의류 분할 모델을 미리 받고, 카메라 권한을 확인하고, 실사 옷 이미지를 미리 불러오고, 혼자 사용 코치를 다시 보이게 한다.
- 결과를 체크리스트로 보여준다.

## 4. 이번 라운드에서 하지 않는 것

- 3D 원단 시뮬레이션, 뒷모습·옆모습 착용: 2D 사진 한 장으로는 품질을 보장할 수 없다.
- 서버 저장·로그인: 시연은 기기 안 저장으로 충분하다.
- 새 카테고리(신발 · 가방): 핵심 흐름을 흐린다.

| 기능 | 결과 | 확인 방법 |
| --- | --- | --- |
| ① 핏 엔진 | 상품마다 핏 스타일 · 성별 기준 사이즈별 실측표를 만들고, 부위별 여유(cm)와 상태를 계산한다. 끼는 사이즈는 크게 감점해 추천한다. 상세 페이지에 부위별 미터 카드가 생겼고, 사이즈표도 실측에서 만든다 | 162cm/50kg 여성은 전부 S, 170cm/62kg 여성은 상품에 따라 S~XL, 175cm/70kg 남성은 대부분 L. 같은 사람도 상품마다 추천이 달라진다 |
| ② AR 핏 맵 | 사이즈를 옷마다 따로 기억하고, 바꾸면 실측 둘레 비율만큼 옷 폭이 변한다. 몸 위 해당 위치에 부위별 라벨(초록 · 주황 · 빨강)이 붙고, 도구 버튼으로 끌 수 있다. 입은 옷을 누르면 그 옷이 사이즈 조절 대상이 된다 | 하의만 XL로 바꾸면 하의 폭만 커지고 상의는 그대로. 착용샷에는 라벨이 빠진다 |

| 시연 준비 | MY에서 한 번 누르면 포즈 · 분할 모델 예열, 카메라 권한, 실사 옷 9벌 · 소매 5벌 준비, 코치 초기화를 체크리스트로 보여준다. 단계마다 제한 시간이 있어 네트워크가 멈춰도 끝난다 | 실제 Chrome에서 5항목 모두 통과 |

남은 한계

- 소매 리깅은 2D 분리라서, 원본 사진에서 팔에 가려졌던 몸판은 원단을 밀어 채운 추정이다. 카메라 속 사용자의 원래 팔이나 옷이 옷 뒤로 비칠 수 있다.
- 실측표는 핏 스타일별 규칙으로 만든 값이다. 실제 브랜드 실측 데이터를 넣으면 같은 계산을 그대로 쓴다.
- 여성복을 체격이 큰 남성이 입는 경우처럼 XL로도 맞지 않으면 추천은 XL이고 라벨에 "끼임"이 그대로 표시된다.
- 실기기(휴대폰) 카메라 체감 확인은 아직 하지 않았다.

## 6. 2차 라운드: 시연이 어떤 환경에서도 무너지지 않게

1차 기능은 완성됐다. 남은 가장 큰 위험은 기능이 아니라 시연 환경이다.

| 남은 문제 | 시연에서 벌어지는 일 | 대응 |
| --- | --- | --- |
| AI 모델 · MediaPipe 엔진 · 폰트를 모두 외부 CDN에서 받음 | 시연장 와이파이가 끊기거나 느리면 AR · 측정 · 옷 등록이 아예 안 됨 | 서비스 워커로 한 번 받은 파일을 기기에 캐시. "시연 준비"를 한 번 누르면 이후 인터넷 없이 동작 |
| 로컬 서버가 `http://localhost` 전용 | 폰 브라우저는 HTTPS가 아니면 카메라를 막음 → 폰으로 시연 불가 | `node scripts/serve.js --https`: 자체 서명 인증서로 같은 와이파이의 폰에서 접속 |
| 측정 전후 차이가 화면에 안 보임 | "측정했더니 뭐가 좋아졌나"를 말로만 설명 | 측정 결과에 "내 치수로 추천 사이즈가 바뀐 상품"을 예시와 함께 표시 |
| AR이 열린 채로 룩 다시 입기 등으로 옷이 바뀌면 상단 상태 문구가 예전 옷 | 발표 화면에 틀린 이름이 보임 | 옷이 바뀌는 모든 경로에서 상태 문구 갱신 |

완료 기준

- 온라인에서 시연 준비 → 네트워크 차단 → 새로고침해도 샘플 AR 추적, 사진 옷 추출이 된다(자동 테스트).
- `--https`로 띄우면 LAN 주소가 출력되고 HTTPS로 앱과 에셋이 열린다.
- 카메라 · 사진 측정 후 결과 카드에 바뀐 상품 수와 예시(상품명 이전 → 이후)가 나온다.

자동 테스트: jsdom 기능 QA 134개, 화면 감사 85개, AR E2E 55개 모두 통과(2026-09-28).

| 항목 | 결과 | 확인 방법 |
| --- | --- | --- |
| 오프라인 시연 | 루트의 `sw.js` 서비스 워커. 앱 · 에셋은 네트워크 우선(수정이 바로 반영, 끊기면 캐시), AI 엔진 · 모델 · 폰트는 캐시 우선. "시연 준비"에 "오프라인 저장" 항목이 생겨 앱 · 에셋 21개, MediaPipe 번들 · wasm, 포즈 · 분할 모델, 폰트 CSS와 한글 subset 92개까지 119개(약 57MB)를 미리 받는다 | E2E: 시연 준비 → 로컬 서버 종료 + 페이지 · 서비스 워커 둘 다 네트워크 차단 → 새로고침. 앱 열림, MediaPipe 로딩, 샘플 AR 추적, 실사 옷 9벌, 사진 옷 추출, 폰트 모두 정상이고 외부 요청 캐시 미스 0 |
| 폰 시연 | `node scripts/serve.js --https`가 기존 http(8765)와 함께 https(8766)를 띄운다. Git for Windows의 openssl로 localhost · 127.0.0.1 · 현재 와이파이 IP가 들어간 자체 서명 인증서를 `.cert/`에 만들고(깃 제외), IP가 바뀌면 다시 만든다. 폰에서 열 주소와 경고 화면 넘기는 법을 출력한다 | E2E: `https://<LAN IP>` 로 열어 보안 컨텍스트 · 카메라 허용 확인 |
| 측정 효과 | 카메라 · 사진 측정 결과 카드에 "내 치수로 추천 사이즈가 바뀐 상품 N개"와 예시 3개(상품명 이전 → 이후)를 보여준다. 변화가 큰 상품, 실사 AR 상품을 먼저 보여주고, 누르면 상세가 열린다. 차이가 없으면 "키·몸무게 추정과 같아요"로 표시한다. 입력값 추정만 한 경우에는 표시하지 않는다 | jsdom: 실측 = 통계 추정이면 0개, 가슴 · 허리 +7cm면 예시 3개와 계산 후 핏 엔진 복귀. E2E: 실제 카메라 측정 후 카드 표시 |
| AR 상태 문구 | 재현되지 않음. `openAR` → `arActivate` → `renderArView`가 이미 `arTracked`를 호출해 옷이 바뀌면 문구가 갱신된다 | 샘플 모드에서 옷을 바꾼 뒤 문구 확인 |

남은 한계

- 폰에서 자체 서명 인증서로 열면 브라우저가 서비스 워커를 막는다. 폰 시연은 카메라 · AR은 되지만 오프라인 저장은 안 되므로, 시연장 와이파이가 불안하면 PC(localhost)로 시연하거나 폰 핫스팟에 PC를 붙인다.
- 카탈로그가 규칙으로 만든 실측표라 상품 간 사이즈 경계가 비슷하다. 175cm/70kg 남성은 둘레가 2cm만 커도 92개 상품이 전부 한 사이즈 올라간다. 실제 브랜드 실측을 넣으면 상품마다 경계가 달라진다.
- 실기기(휴대폰) 카메라 체감 확인은 여전히 필요하다.
